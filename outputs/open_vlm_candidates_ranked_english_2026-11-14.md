The ranking is a **qualitative testing priority for this project**, based on task fit, ease of reproducible deployment, likely GPU cost, and value as a comparison model. It is **not a measured accuracy ranking**. Parameter counts generally follow model names; MoE rows distinguish total from active parameters. Context length is a token limit, not a guarantee of video duration or frame capacity. “To verify” means the selected checkpoint and inference setup must be checked before testing. Open weights do not necessarily mean an OSI-approved open-source license.

## Deployment-column interpretation

- **vLLM API, SGLang API, and LMDeploy API** refer to server runtimes that can expose an HTTP endpoint. Their video support is model- and version-specific; the table notes exceptions. See the [vLLM multimodal support matrix](https://docs.vllm.ai/en/stable/models/supported_models/) and the [LMDeploy model list](https://github.com/InternLM/lmdeploy/blob/main/docs/en/supported_models/supported_models.md).
- **Transformers Python** means the checkpoint can be loaded for Python inference; for a remote endpoint, the lab would wrap it in a small service such as FastAPI. This is not a claim of plug-and-play vLLM-compatible serving.
- A framework being listed means its official documentation or the model card identifies a supported path, **not** that it has been tested on the lab GPU server. Verify the exact checkpoint, runtime version, video input path, and output format before batch evaluation.
