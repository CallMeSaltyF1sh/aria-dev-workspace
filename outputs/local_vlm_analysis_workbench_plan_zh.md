# 本地 Aria 阶段识别工作台方案（v4）

本文是界面与数据流程方案。交互概念稿通过虚构样例展示流程，文件索引、数据库和 Gateway 任务执行属于本地应用实现。此前的两视频 Gateway pilot 方法见 `preliminary_vercel_gateway_vlm_pilot_plan_zh.md`，逐页调整依据见 `vlm_workbench_design_review_plan_zh.md`。

## 1. 产品目标与导航

工作台在本机启动，通过浏览器访问。它把 `data/` 作为素材目录，把人工阶段时间轴作为评估真值，按固定抽帧规则调用 VLM，并保留可复查的任务、Prompt 和评估记录。只有用户启动模型任务时，选中的帧才提交给 Gateway。人工标签、参与者叙述和评估结果不进入模型输入。

**采用四个主菜单，比三个更清楚：**

| 菜单名（建议英文 UI） | 页面职责 | 主要入口 |
| --- | --- | --- |
| **Data Library** | 扫描和管理 `data/` 目录；查看 MP4/VRS；进入素材详情并人工标注 | 素材列表、目录树、导入、新建目录、素材详情 |
| **Prompt Library** | 编辑阶段定义、模板与 JSON 输出协议；保存不可变版本；在开发素材上试运行并比较 Prompt | Prompt 列表、版本详情、测试记录 |
| **VLM Tasks** | 选择单个或多个素材、模型、Prompt 版本和抽帧设置；执行并追踪每个素材的状态 | 新建任务、任务列表、任务详情 |
| **Evaluation** | 选择完成的任务与锁定的人工标注比对；查看指标、边界和具体错误 | 评估列表、结果页、错误案例 |

不再单列 Annotation、Frames、Errors：人工标注与抽帧预览在**素材详情**；错误审查在 **Evaluation**。Prompt 值得独立成页，因为它有自己的草稿、版本、测试记录和比较过程。VLM Tasks 仅**引用已保存的 Prompt 版本**，避免一个任务里的临时修改覆盖实验配置。

侧边栏只展示上述四项。各页内部用标签页或局部导航承载次级功能，不继续扩张主菜单。建议全局页头显示当前工作区、Gateway 配置状态和正在运行的任务数量。

```text
Data Library → 素材详情 / 人工标注 → 锁定标注
Prompt Library → 保存版本 / 小样本试运行
VLM Tasks → 选素材 + 模型 + Prompt 版本 + 抽帧配置 → 运行
Evaluation → 选完成的任务 + 锁定标注版本 → 计算与审查
```

## 2. Data Library：`data/` 的可视化目录

### 2.1 目录与素材列表

列表分别显示素材可用性和标注状态，允许独立筛选。Metadata 记录匿名参与者 ID、试次、衣物、条件、数据划分和 RGB 是否带阶段文字覆盖。数据划分以参与者为单位，文件夹用于组织。Frames & QC 点击生成后，整段录像按 0.1 秒抽帧；显示处理进度、缓存目录和总帧数，每页浏览 24 张图及其请求/实际时间与偏差。Related Tasks 直接链接对应任务。

- 打开页面时扫描项目 `data/` 下的**子目录和 MP4/VRS 原始录像**，仅建立或更新素材索引；支持手动刷新、搜索、按类型/目录/标注状态筛选、排序。扫描目录和浏览视频不会生成帧，图片与抽帧缓存不出现在素材列表。
- 左侧目录树显示 `data/` 及其子目录；右侧列表显示当前目录或递归视图。可新建、重命名和删除子目录。删除非空子目录时必须先展示递归影响的文件数量及关联记录，并在二次确认后直接删除目录及其内容；`data/` 根目录不可删除。未来可用 `development/`、`test/` 等目录组织素材，但正式数据集划分仍需以参与者为单位记录，不能只靠目录名推断。
- 每行显示文件名、相对路径、格式、时长、大小、解析状态、标注状态、已关联任务数；可在详情页查看分辨率、帧率、输入类型等元数据。扫描遇到无法解析或缺失文件时显示原因，不让整个列表失败。
- 添加素材时选择目标子目录，复制 MP4/VRS 到 `data/`；导入前预览目标路径、同名冲突和预计磁盘占用。文件复制成功后再登记到数据库，失败则清理未完成的临时文件。重复内容由哈希提示，用户可取消或明确保留副本。
- 支持单个删除和批量删除。删除确认框明确写出**将直接删除 `data/` 下选中的实际文件**，列出文件数、目录及受影响的标注/任务引用；用户须二次确认。目录批量删除同样按递归清单确认，禁止静默级联。
- 如果文件被已锁定标注、已完成任务或评估引用，删除前列出依赖并禁止无提示的级联删除。建议保留不可变的历史记录和文件哈希，将该素材标记为 `source_missing`；历史结果仍可查，但无法重新播放或抽帧。删除不会静默修改已有任务结果。
- 目录树只允许操作 `data/` 内真实路径；不跟随指向目录外的符号链接，防止错误扫描或删除。扫描变化时按路径、大小、修改时间和必要时哈希更新索引；外部直接增删 `data/` 文件后可刷新同步。

### 2.2 MP4 与 VRS 的展示边界

**标注导出（2026-11-24）：**Annotation 保存后可导出当前视频 CSV/JSON；未保存编辑时需先保存。Data Library 的 Export annotations 导出所有目录中至少含一个合法阶段标签的已保存草稿，与列表筛选/选择无关。导出前显示录像数、片段数、未分类数。保留部分标注中的空标签，源缺失或变化的历史标注附 source_status 与原始源哈希，不误称为当前录像的标注。JSON 包含阶段定义及逐视频记录，CSV 每段一行并附素材相对标识、源哈希、起止毫秒/秒及版本。真实标注及导出文件留在 Git 外，按需要单独共享；不包含视频、frames、study 元数据或本机绝对路径。

MP4 可直接使用浏览器支持的编码播放；若浏览器不支持其编码，后端生成本地预览代理。VRS **不能假定浏览器原生播放**：保留原始 `.vrs`，用 Project Aria Tools 读取 RGB 流和时间戳，生成可播放的本地 MP4/HLS 代理与缩略图。预览代理、帧缓存保存在 `workspace/`，不覆盖 `data/` 原文件。VRS 中是否存在 RGB 流、标定信息及其他传感器流以实际文件检查结果为准。

MP4 标注按解码后媒体时间定位；VRS 标注界面显示相对录像起点的时间，同时保存到 `DEVICE_TIME` 的映射。VRS 模型抽帧与人工标注使用同一映射，记录请求时间和实际返回帧时间。MP4 若是从 VRS 导出的，只有存在可靠时间映射时才关联到原始 VRS；不能仅凭文件名或同时按下录制键推定同步。

### 2.3 素材详情与前后导航

点击列表条目进入素材详情。页头显示相对路径、格式、播放/解析状态，并有 **Previous item** 和 **Next item** 按钮。顺序采用进入详情时的**当前筛选和排序结果**；第一个禁用 Previous，最后一个禁用 Next。列表刷新或删除导致当前条目消失时，回到列表并提示。按钮切换素材前，未保存的标注应自动保存草稿或提示处理，不静默丢失编辑。

详情页包括“Video & Annotation”“Metadata”“Frames & QC”“Related Tasks”四个页面级标签。标签栏独立于播放器，每次只显示当前标签的内容。只有 “Video & Annotation” 显示播放器和标注；其余三个分别显示素材元数据、抽帧与质量检查、关联的 VLM 任务。现有人工标注 CSV 可导入到相应素材，先校验时长与区间，再让标注者检查并保存为版本。

## 3. 在视频预览中直接做人工标注

### 3.1 交互方式

播放器操作栏显示播放进度条、当前时间和总时长，可选 0.5×、0.75×、1×、1.25×、1.5×、2×。Play 左右的 **1 frame** 按钮前进或后退一帧。下方 **Annotation** 使用独立的标注轴，分割点直接位于轴线上。可点击轴线添加分割点，也可用 **Add split point** 从当前播放位置添加，两者均吸附到最近的 0.1 秒。

每两个相邻分割点以及视频起止点构成一个片段。分割点按 0.1 秒拖动，内部片段至少长 0.1 秒，真实末段可更短以保留原始结束时间，两端以固定的视频起止时间为界。悬停、拖动或选中分割点时，用气泡显示该点的时间。选中后可点 **Delete split point**，也可在分割点获得键盘焦点时按 Delete 或 Backspace。删除会合并两侧片段，标签一致时保留原标签，否则将合并后的片段留作待标注。每段直接在色条上选择 `P0`—`P4` / `unclear`，下方图例显示阶段定义和对应颜色。点击 **Save** 保存草稿，评估时按下方规则创建不可变快照。

### 3.2 区间规则与校验

- 保存为半开区间 `[start_ms, end_ms)`；同一时间点只属于右侧新片段。
- **不允许重叠、零长度、负时间或超出实际时长**。添加/拖动分割点时即限制范围，保存时由后端再次校验。
- 草稿可有“尚未分类”片段，以便逐步标注；**创建评估快照前要求从 0 到视频结束全部覆盖且每段有一个合法标签**。真正没有衣物动作时标 `P0`；无法从画面判断时标 `unclear`，不要把未标注空白自动当作 P0。
- 第一段从 0 开始，最后一段在实际媒体结束处截止。已知测试 CSV 的末端略超出媒体时长，应在导入时提示标注者修正，不能静默截断原始版本。
- 锁定后禁止就地改写；任何修订创建新版本。多人标注时每位标注者先独立锁定，避免看到他人或模型预测后被影响。
- 模型预测轨道仅在锁定后、且从评估结果返回该素材时显示；标注模式默认隐藏。

**播放器区域：**画面 → 含 Add split point 的播放控制 → 分割点轨道 → 每段可直接选阶段的时间轴 → 时间刻度。抽帧预览放在素材详情的 Frames & QC 局部标签页。打开此标签默认不抽帧。点击 **Generate frames** 后为整段录像生成固定 0.1 秒间隔的本地帧缓存，不再设置 Target time、Frames per group 或 Frame spacing。

### 3.3 标注文件与评估版本

点击 **Save** 时，本地后端按需创建 `workspace/annotations/<asset_id>/`，把当前时间轴写入 `draft.json`。该目录与 `workspace/frames/<asset_id>/` 使用同一个稳定素材 ID，`data/` 专门存放原始录像。写入完成后才显示 **Saved**。保存失败时保留当前未保存的编辑，可重试。

```text
workspace/annotations/<asset_id>/
  draft.json
  versions/
    v001.json
    v002.json
```

JSON 记录素材 ID 与源录像哈希、标注者 ID、时间基准、录像时长、阶段定义版本、保存时间，以及每段的 `start_ms`、`end_ms` 和 `phase`。MP4 使用媒体时间，VRS 记录相对录像起点的时间及对应的 `DEVICE_TIME` 映射引用。用于评估时，将校验通过的标注另存为不可变的版本文件。评估记录引用确切版本及内容哈希，再次点击 **Save** 只更新草稿。多人标注时，每位标注者使用独立草稿，保存路径在素材 ID 下再按标注者 ID 区分。

## 4. Prompt Library：把 Prompt 调优单独管理

**页面结构**：列表按 Prompt 家族归组，每行显示已发布版本、草稿和最近测试。详情配有 Template、Versions、Tests。Template 显示系统指令、用户模板、变量和输出协议；Versions 查看不可变历史和文本差异；Tests 负责固定目标集、实际输入预览、逐目标 A/B 对比与历史记录。

Template 直接编辑当前工作副本，显示 Published、Unsaved 或 Saved draft。Save 仅保存草稿，允许保存未写完的内容；Publish new version 校验当前内容并发布为新的不可变版本。Quick test 使用编辑器当前内容，即使尚未保存也可对一个开发集目标点试跑。展示渲染后的输入和响应，编辑内容或切换测试配置后标记结果已过期。单点试跑供即时调试，Tests 用于固定样本的可复现测试和 A/B 对比。测试成功不是发布的强制条件。

**实验合同**：A/B 一次只比较 Prompt。对照组使用同一个模型、provider、采样目标、实际帧顺序和推理参数。已保存并创建快照的人标只在结果侧显示。发布前核对标注图例、Prompt 与解析器引用同一版阶段定义。这里把 `unclear` 视为合法预测，`invalid_output` 代表格式不符合约定。视觉输入优先 clean RGB，带答案覆盖的旧录像需要单独标记并排除出正式识别对比。

在 Data Library 的素材详情进入 **Frames & QC**，点击 **Generate frames** 生成整段录像的帧缓存：0、100、200…ms，结束点采用开区间。每个请求选择最近的原始帧，等距取较早帧；重复命中同一原始帧时只保存一张 JPEG，清单保留全部请求时间与实际时间映射。MP4 顺序解码一次，VRS 复用 provider 并使用 DEVICE_TIME；缓存完成后原子发布。

Prompt Library 从已生成的开发集全视频缓存摘要读取选项。**Quick test 单选一套缓存，Tests 可选一套或多套**。测试目标时间与上下文帧设置移到 Prompt 测试/任务模块；批量测试统一指定推理采样规则，实际目标与所选帧记录进运行快照。A/B 使用相同目标及 JPEG 输入。生成所有帧不等于全部提交 VLM，没有缓存时引导到 Frames & QC 生成。

Tests 支持 **Single test** 和 **A/B comparison**。单测结果展示有效响应数、与锁定人标一致数、格式无效数及逐目标预测；没有人标时不计算一致数。A/B 使用同一批目标，显示 A 和 B 各自的结果以及变化列，支持只看发生变化的目标。有效预测的对错变化和格式恢复分别统计。点开某个目标可检查共用输入帧和每版原始响应。两种测试都保留在历史中。

每个 Prompt 有名称、用途、阶段定义、system/user 模板、允许标签、JSON schema、变量说明、创建者和说明。支持草稿编辑、复制成新版本、版本差异查看、归档；**发布后版本不可原地修改**。VLM Tasks 只选择已发布版本，运行时再保存 Prompt 完整文本、schema 和内容哈希的快照。

Prompt 页面使用所选开发集帧组进行单次试运行或 A/B 小样本比较。保存每次 Prompt 版本、帧组清单、原始响应、解析结果、用量和费用。Prompt 编辑器应提供变量预览与 JSON 输出校验。对比视图展示逐目标差异和基本指标，并标明这是开发集调优结果，不能把测试集结果用于反复选择 Prompt 后仍当作独立测试成绩。

不要在 VLM Tasks 中放一套独立的 Prompt 编辑器。任务创建表单只显示 Prompt 版本下拉、只读预览和“前往 Prompt Library 创建/修改”入口。这样一次任务的配置可冻结、可回放。

## 5. VLM Tasks：多素材任务与逐项进度

任务列表和详情都显示任务创建时间。新建任务时，从本地服务扫描的 `data/` 素材清单中多选 MP4 或 VRS。模型可选 `alibaba/qwen3.8-27b`、`alibaba/qwen3.7-flash`、`alibaba/qwen3-vl-instruct`，也可通过 Custom 输入完整模型 ID。抽帧分别设置目标时间戳间隔（秒）和每个目标的输入帧数。

推荐的首版抽帧规则：录像相对时间从 0 起按间隔生成目标，末端采用开区间，模型只判目标时刻。每组优先包含目标帧，其余请求时间按固定偏移放在两侧。若默认窗口取一个采样间隔，可用「间隔 ÷ 帧数」作为偏移步长；偶数帧时明确把多的一张放在较早一侧。越界或重复的实际帧省略并记入清单；没有可用目标帧则记录输入失败。固定目标集可直接复用显式偏移，例如 2 秒间隔和 5 帧的偏移为 −0.8、−0.4、0、+0.4、+0.8 秒。任务列表同时展示已处理目标数、有效预测数、模型与 Prompt 版本。详情保留固定配置、目标级响应与尝试历史，并提供 Evaluation 入口。

VLM Task 启动后由后端检查并复用全视频 0.1 秒帧缓存，缺少时通过同一生成流程准备。手动生成同样写入 `workspace/frames/<asset_id>/<set_id>/`，包含 JPEG 和 schema v2 的 manifest.json。set_id 由源文件哈希、流、时间基准、全视频模式、100ms 间隔、分辨率和抽帧版本匹配。清单记录每张图对应的全部请求时间、实际时间、原始索引与尺寸；VRS 记录 DEVICE_TIME。预测目标和上下文帧从缓存中按统一规则选择，写入独立的任务输入清单，不修改缓存。若未来需要高于 10 fps 的分析，需另行定义缓存配置，当前界面固定为 0.1 秒。Preview 和 Dry run 不发送模型请求；VRS 播放代理与帧缓存均与 data/ 原件分开。

Request cap 是任务允许发起的 API 请求次数上限，包含重试。Cost cap 是决定何时停止发起新请求的美元预算阈值，已发出的请求可能继续计费。Dry run 只在本地检查配置，正式实现时也会预览目标点、帧和预计请求数。单目标 smoke test 会实际调用一次模型。保留已发布 Prompt 版本、provider/routing、实际帧偏移与分辨率、推理参数及重试规则，供实验复查。

任务详情同时展示总进度和**逐素材进度**：

| 层级 | 状态 |
| --- | --- |
| 任务 | `queued`、`running`、`partially_completed`、`completed`、`failed`、`cancelled` |
| 素材 | `queued`、`preparing`、`running`、`completed`、`failed`、`skipped`、`cancelled` |
| 目标请求 | `pending`、`running`、`valid`、`unclear`、`invalid_output`、`request_failed` |

逐素材行显示已完成/总目标点、成功/失败数、最近更新时间和错误摘要。展开可查看失败目标时间、错误类别、可读错误信息、重试次数和原始响应（若已收到）。网络超时、权限/额度错误、媒体解码错误、schema 无效应分开显示；认证 Header/API Key 不得进入日志或页面。允许取消、按固定策略重试失败项和断点继续；重试保留原 attempt 记录，不覆盖原错误。状态更新可由本地后端事件推送到页面，刷新后从持久化任务状态恢复。

每次任务生成不可变 manifest：素材 ID/文件哈希、模型与实际 provider、Prompt 版本及文本哈希、采样规则、目标时间、每帧请求与实际时间、推理参数、软件版本、运行时间和费用。若配置改变，新建任务。任务完成与否由所有素材状态推导，不能在部分失败时误显示 `completed`。

## 6. Evaluation：指标与错误位置

选择**已完成**的 VLM Task，或选择 `partially_completed` 任务只评估成功部分并明确覆盖率；然后选择已保存的人工标注快照。可按素材、目录、条件和阶段筛选。计算前先检查素材哈希、标注时长、target 时间、Prompt/模型配置及人工版本；缺失或不一致的目标点单独列出。若任务创建时尚无标注，模型仍可运行，但评估必须等人工标注保存、校验并生成快照。

首页提供目标时间戳级别的 accuracy、macro F1、每阶段 precision/recall/F1/support、confusion matrix、`unclear` rate、`invalid_output` rate、请求失败率和覆盖率；分母与排除规则须清楚。点击矩阵单元格或错误列表跳转至素材详情的对应时间点，并打开并排比较视图：目标帧、人工标签、模型标签、证据、原始响应、Prompt 版本、请求状态及可记录的人工错误原因。

**边界错误与阶段错误分开看**：在人工分割点前后显示模型的目标点预测，统计边界邻域的错判率。只有预先确定把离散预测合并为区间的规则后，才计算 segmental F1、edit score 或边界时间误差；不能把稀疏采样的 target accuracy 称为逐帧准确率。Prompt/模型比较只对同一批目标点、等价的输入帧和同一人工真值版本给出直接可比结论，否则页面警告。

错误案例可由研究者标记 `phase_boundary`、`occlusion`、`fast_motion`、`repeated_action`、`insufficient_context`、`annotation_ambiguity` 等原因。模型的自述证据只是预测文本，不自动成为错误原因的真值。支持导出指标 CSV/JSON、混淆矩阵图、目标级结果、错误案例和完整 manifest。

## 7. 本地数据与实现建议

继续使用本地 Web 架构：React + TypeScript 前端，FastAPI + Python 3.12 后端，SQLite 记录索引/版本/任务/结果，FFmpeg 处理 MP4，Project Aria Tools 处理 VRS。`.env.local` 中的 Gateway Key 仅由后端读取，页面只显示配置状态。

```text
projectaria-tools/
  data/                          用户直接管理的原始 MP4/VRS 与子目录
  app/frontend/                  四个主页面与素材详情
  app/backend/                   扫描、导入、标注、任务、评估 API
  workspace/app.db               本地索引与任务状态
  workspace/previews/            VRS/非兼容编码的本地播放代理
  workspace/frames/              可重建的抽帧缓存
  workspace/annotations/         按素材 ID 保存人工标注草稿和固定评估版本
  outputs/vlm_pilot/             标注、manifest、预测、指标导出
  .env.local                     本地密钥，不提交版本控制
```

推荐实体：`assets`、`directories`（可选，目录也可由扫描产生）、`annotation_sets`、`prompt_versions`、`prompt_tests`、`tasks`、`task_assets`、`targets`、`frames`、`attempts`、`predictions`、`evaluations`、`error_reviews`。人工标注区间以 JSON 文件为准，SQLite 记录标注的相对路径、版本、哈希和引用关系。素材移入其他子目录时应更新路径索引，并保留稳定 asset ID 与内容哈希。

## 8. 实施顺序与验收

1. **Data Library + 人工标注：**扫描当前 `data/`，展示两条素材；完成文件/目录添加、删除确认和前后导航；导入现有 CSV，在播放器时间轴上修正并保存阶段草稿。验收：每段不重叠、全时长覆盖、末端越界被发现，导出后与保存版本一致。
2. **Prompt Library + 单目标运行：**保存初始 Prompt 版本、固定五帧预览，在选定开发素材上完成一条可追踪请求；严格校验 JSON，把 `unclear` 与 `invalid_output` 分开。
3. **VLM Tasks：**选择多个素材，显示逐素材进度、失败原因、重试记录和费用；中断后可恢复，manifest 可重建输入。
4. **Evaluation：**选择完成的任务和锁定标注，计算目标级指标；从混淆矩阵跳转到视频错误位置，支持导出。
5. **VRS 扩展：**原始 VRS 扫描、RGB 流检查、预览代理、`DEVICE_TIME` 映射及直接抽帧；正式数据集的参与者级划分与条件比较随后加入。

第一版不做账号系统、云端数据库、多人实时协作、Agent 自主改 Prompt、模型微调或 OptiTrack 三维展示。当前两条测试视频适合验证交互和流水线，不足以给出模型普遍准确率。
