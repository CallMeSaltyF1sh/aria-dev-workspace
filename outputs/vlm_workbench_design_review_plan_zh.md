# Aria 工作台设计评审与调整计划

范围：Data Library、Prompt Library、VLM Tasks 及其子页面。依据现有概念稿、两段试验视频的分析方案和本地工作台方案。这里记录待调整项。

工作台要回答两个问题：模型能否识别指定时间点的穿衣阶段，以及在输入相同的情况下，改 Prompt 或换模型会带来什么变化。界面需要让研究者复查素材来源、实际输入帧、模型配置和人工标注版本。

## 1. Prompt Library：优先调整

| 页面 | 现状与问题 | 调整 |
| --- | --- | --- |
| Prompt 列表 | v1、v2 以同名条目并列，另一个草稿看起来像完全独立的 Prompt。找不到基线、最新版和草稿之间的关系。 | 一行一个 Prompt。显示当前发布版本、草稿状态和最近测试。进入详情再看历史。明确标记常用基线，但任务仍选择确切版本。 |
| 版本详情与编辑器 | 当前主要是只读文本和标签名。没有把阶段含义、相邻阶段判定规则、目标帧和输出校验放到具体可预览的状态。 | 详情设为 **Template、Versions、Tests**。Template 展示可验证的 system/user 模板、变量、标签规范和输出 schema。发布版只读，可复制为草稿，保存后单独发布。版本差异并排显示 Prompt 和输出规则的变化。 |
| 测试设置 | 当前只有示意素材、目标数和模型下拉，缺少具体帧及可复用的测试配置。 | 建立仅供开发集使用的 **Test set**，保存素材 ID、目标时间戳及顺序。两个版本共用同一组实际帧、模型、路由和推理参数。运行前预览目标帧标记、邻帧、实际帧时间和渲染后的完整 Prompt。 |
| 测试历史与比较 | 当前「Version comparison」只显示是否跑过，无法看版本在哪些时间点改变判断。 | 增加逐目标对比页。显示时间戳、共有帧、人标阶段（如果已锁定）、A/B 预测、证据、状态和原始响应。先看改变的预测、阶段边界和遮挡例子，再看汇总分数。记录输入快照、实际 provider、费用和失败。可复用历史配置重跑。 |

首版模板建议使用一个明确的输出协议 `{"phase":"…","evidence":"…"}`。把 P0–P4 和 `unclear` 的定义作为一份带版本的标签规范，供标注图例、Prompt 和解析器引用。明确 `unclear` 是视觉证据不足时的有效预测，`invalid_output` 是模型响应格式错误。人标只用于结果比对，尤其要检查渲染后的输入是否意外带入阶段标签或原视频上的标注覆盖层。

公平比较的验收例：用同样的五个开发集目标点跑 v1 和 v2。预览中的输入图片和顺序一致，每个目标能看出预测从什么变成什么。改了模型、帧或目标集时，页面明确说明这些结果无法归因于 Prompt 单独变化。

## 2. Data Library：补足素材是否能用的判断

| 页面 | 优先调整 |
| --- | --- |
| 素材列表与目录 | 将 **Media readiness** 与 **Annotation status** 分成两列或两个独立筛选。VRS 无 RGB 属于素材状态，草稿或已锁定属于标注状态。补导入目标目录、重名处理、扫描失败和空状态；删除预览展示真实文件以及关联任务和标注的影响。 |
| Video & Annotation | 补 CSV 导入预览、未标注区间提示、保存草稿与锁定版本两种状态。导入遇到越界时允许先检查和修订。换素材时保护未保存草稿。确认 pilot 是否有小于 1 秒的有效阶段，再决定正式版最短片段限制。 |
| Metadata | 补试次 ID、参与者匿名 ID、衣物、实验条件、数据集划分，以及 RGB 是否有阶段文字覆盖。文件夹用于组织。以匿名参与者 ID 核对开发集和测试集隔离。 |
| Frames & QC | 用 1 个目标点展示请求时间、实际帧时间、偏差和按时间排序的 RGB 帧。VRS 标明 `DEVICE_TIME` 映射，MP4 标明媒体时间。补 VRS RGB 缺失、需要生成预览代理或解码失败时的状态。 |
| Related Tasks | 每条链接直接打开对应任务详情；关联材料缺失时仍可查看已保存的历史结果。 |

## 3. VLM Tasks：把配置、执行和排查串起来

| 页面 | 优先调整 |
| --- | --- |
| 任务列表 | 保留创建时间、状态与黑色进度条。补模型和固定 Prompt 版本；任务较多时通过状态筛选。区分「已处理目标数」和「有效预测数」，避免运行结束被误读为所有目标都成功。 |
| 新建任务 | 用同一份 Data Library 索引多选素材，显示无法解码或不适合对比的素材原因。允许选已发布 Prompt 版本并只读预览。除间隔和帧数外，明确上下文帧如何分布、如何标出目标帧、靠近起止点时如何取帧。Dry run 显示预计目标数、请求数和一组真实输入预览。已保存的任务配置可复制为新任务。 |
| 任务详情与素材结果 | 补完整配置快照、每素材结果和目标点明细、预测与原始响应、失败重试记录。分开显示无法抽帧、请求失败、输出无效和有效的 `unclear`。重试保留原尝试记录，完成后可转到 Evaluation，并显示成功覆盖率。 |

## 实施顺序

1. **先定共享规则**：阶段规范、目标帧与邻帧的位置、时间基准、如何处理有标注覆盖层的旧素材、开发集与测试集的划分。
2. **先出 Prompt Library 的新稿**：列表 → 编辑草稿和版本 → 固定目标集 → 输入预览 → A/B 结果与历史。用一组模拟输入串通完整交互。
3. **再补 Data Library**：优先完成素材可用状态、实验元数据、Frames & QC 与标注锁定。本轮方法验证优先走 MP4，同步展现 VRS 未准备好的状态。
4. **最后串起 VLM Tasks**：发布的 Prompt 能进入任务，同一测试配置能复制，单个任务能追到每个目标的输入帧、响应和失败原因，再连接 Evaluation。
