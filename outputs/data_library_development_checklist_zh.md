# Data Library 第一阶段开发确认清单

状态：待用户确认。范围覆盖素材列表、目录与文件操作、视频详情、人工标注和手动抽帧。本文件明确开发决策与验收标准。

## 技术栈

| 层级 | 拟采用 | 选择理由 |
| --- | --- | --- |
| 前端 | React + TypeScript strict + Vite，npm 锁文件 | 本地桌面浏览器应用，独立 Python 媒体后端。支持清晰的组件边界与类型检查。 |
| 路由和服务数据 | React Router、TanStack Query，标注编辑使用局部 reducer | URL 记录素材、标签页和列表筛选；服务数据统一刷新，时间轴操作集中处理。 |
| UI | CSS Modules + 共享设计变量，Radix Dialog/Dropdown/Tooltip 等交互原语，Tabler Icons | 延续黑白灰、Geist/Geist Mono、黑色主按钮及既定图标；复用可访问的弹窗和键盘交互。 |
| 后端 | Python 3.12 + FastAPI + Pydantic + Uvicorn | 文件扫描、标注校验、抽帧与 Aria Python API 在同一个本地服务完成。 |
| 数据索引 | SQLite + SQLAlchemy 2 + Alembic | 保存稳定素材 ID、路径、元数据、帧组和引用关系，迁移可追踪。JSON 标注文件是区间内容来源。 |
| 媒体 | FFmpeg + ffprobe；Project Aria Tools | MP4 元数据、时间戳、代理与抽帧；VRS 流、标定及 DEVICE_TIME 映射。 |
| 工程检查 | ESLint、TypeScript、Ruff；pytest，Playwright 核心流程 | 测试集中覆盖路径与删除、保存冲突、时间轴、准确抽帧和浏览器流程。 |

开发时通过 Vite 的 /api 代理连接本地 FastAPI；打包后由 FastAPI 提供页面和媒体接口。默认只监听 127.0.0.1。前端调用以素材 ID 为入口，后端解析真实路径。依赖在实施时确认兼容版本并锁定。

参考依据：[React 的 Vite 与 TypeScript 说明](https://react.dev/learn/build-a-react-app-from-scratch)、[Vite 环境要求](https://v8.vite.dev/guide/)。

## 需要确认的设计决策

| 项目 | 目前的不一致或遗漏 | 推荐实施规则 |
| --- | --- | --- |
| 最短片段 | 旧规则仍限制至少 1 秒，边界精度已改为 0.1 秒 | 最短改为 0.1 秒，相邻内部分隔点至少相差 0.1 秒。录像真实起止时间保留原精度，允许末段短于 0.1 秒，以便完整覆盖。 |
| Save 与评估版本 | 设计已移除 Lock version，旧文档仍要求先锁定 | 页面只保留 Save。未来创建评估时，从已保存且校验通过的草稿生成不可变快照。第一阶段预留快照数据结构。 |
| VRS 交付 | 需要支持 VRS，但当前没有真实 VRS 样例 | 第一阶段完成扫描、格式识别、可用流检查及代理/抽帧适配。无真实样例前只报告 MP4 端到端验收，VRS 的真实时钟映射和画面验收保留明确状态。 |
| CSV 旧标注 | 用户删除了 Review CSV import 入口 | 首次开发通过一次显式迁移导入已有 CSV，经预览批准后生成新草稿。原 CSV 保留，界面不恢复旧按钮。 |
| 退出编辑 | 旧方案允许自动保存或提示，尚未选定 | 素材切换或离开页面时，提供 Save and leave、Discard changes、Stay。关闭窗口使用浏览器未保存提醒。 |
| 删除及并发操作 | 删除会直接操作 data/；运行中的媒体处理可能引用文件 | 确认弹窗列出实际对象与引用，正在读取/处理的素材先拒绝删除并说明原因。完成后可重试。已生成帧与标注保留，源文件标记 missing。 |

## 数据合同

工作目录由后端集中配置，默认指向当前项目。

```text
data/                                   原始 MP4/VRS
app/frontend/                           React 应用
app/backend/                            Python 应用与独立环境
workspace/app.db                         素材、标注、帧组和处理任务索引
workspace/previews/<asset_id>/           可重建播放代理和时间映射
workspace/annotations/<asset_id>/
  draft.json
  versions/v001.json                     后续评估快照
workspace/frames/<asset_id>/<group_id>/
  frame_0001.jpg
  manifest.json
```

group_id 表示单个目标点的一组帧，替代此前含义不够清楚的 sampling_id。缓存匹配仍由源哈希、流、目标时间、请求偏移、分辨率、抽帧版本等共同决定。每组包含目标帧、上下文帧和清单。图片不会加入原录像列表。

- 标注内部用整数毫秒，半开区间 [start_ms,end_ms)。0.1 秒吸附用于可编辑边界，不舍入录像真实结束时间。
- 未分类使用 null，unclear 是独立有效标签。P0–P4/unclear 共用一份带版本的阶段定义，供图例和后续 Prompt 使用。
- annotation draft 记录 asset_id、源哈希、时长、时间基准、schema/标签版本、revision、区间和保存时间。保存失败不显示 Saved。
- 帧清单记录帧组 ID、素材及源哈希、目标时间、每张图的请求时间/实际时间/相对路径、目标帧身份、分辨率与提取参数。VRS 保留 DEVICE_TIME 与预览媒体时间映射；同一实际帧去重。
- 文件原地替换后，标注和帧组必须显示 source changed 并重新检查。路径移动尽量保留稳定 ID，内容重复保留独立素材记录并提示相同哈希。

## 开发与验收 checklist

### A. 工程与基础数据

- [ ] 建立 app/frontend、app/backend，依赖锁定、环境说明和统一启动入口。
- [ ] 前端按 Data Library 功能组织组件，后端按资产、标注、帧组服务划分；路由层集中校验参数。
- [ ] 建立数据库迁移和素材稳定 ID；定义 API 请求/响应模型，前端类型由 OpenAPI 生成。
- [ ] 源路径只允许落在 data/ 内，拒绝目录穿越及越界符号链接；子进程参数用数组传入。
- [ ] 阻塞媒体处理进入后台工作队列，返回处理 ID；状态写入数据库，重启后处理中条目标记 interrupted 并允许重试。
- [ ] JSON/帧目录采用同目录临时文件或临时目录写入，再原子替换。重复点击不会产生并发重复结果。索引失败时可从清单恢复。

### B. Data Library 列表和目录

- [ ] 页面首次打开和 Scan data/ 均扫描原录像，支持目录、搜索、排序及格式/媒体状态/标注状态筛选。
- [ ] 扫描只做索引与元数据检查，不批量生成帧；坏文件隔离显示错误。
- [ ] 列表显示名称、相对路径、格式、时长、媒体状态和标注状态；大小等次要信息收进详情。
- [ ] 支持目录新增、重命名和删除，根目录固定；目录选择与列表视图保持一致。
- [ ] 添加文件通过流式上传/复制进入选定目录。重名提供取消、跳过或新名字，复制失败清理未完成对象。
- [ ] 单个/批量删除先展示影响预览，再明确确认删除真实 data/ 文件。用临时测试目录验证删除流程。
- [ ] 文件外部增删或替换后刷新能同步；素材 missing 时已有标注和缓存引用仍能查看。
- [ ] 真实空、无搜索结果、扫描中、解析失败均有明确状态。

### C. Video detail 与标注

- [ ] 列表进入详情，并按进入时的筛选/排序实现上一个和下一个；首尾禁用，返回恢复列表上下文。
- [ ] Video & Annotation、Metadata、Frames & QC、Related Tasks 是页面级标签，仅显示当前内容。
- [ ] MP4 本地播放接口支持 Range 和 seek。代理按需准备，显示处理进度及失败原因。
- [ ] 播放控件含当前/总时间、播放进度、逐帧前后、0.5/0.75/1/1.25/1.5/2 倍速。
- [ ] 逐帧按真实解码时间戳定位，变帧率录像不以 1/fps 近似。
- [ ] 初始标注覆盖全视频、标签留空；Save 写入真实 draft.json，重启和刷新后恢复。
- [ ] 分隔点添加、0.1 秒拖动、hover/选中时间气泡、实心黑选中、点击其他位置取消。
- [ ] 小型菱形与轴线中心对齐，点击区域可操作；键盘左右移动，Delete/Backspace 删除。
- [ ] 删除合并两侧片段，相同标签保留、不同则留空；文字输入获得焦点时删除键不影响时间轴。
- [ ] P0–P4/unclear 图例、颜色、片段选择和未分类状态一致；保存可含未分类。
- [ ] Save 使用 revision 校验，多标签页旧草稿不能覆盖新草稿，冲突提示重新载入。
- [ ] Metadata 支持匿名参与者、试次、衣物、视觉条件、数据划分、覆盖层状态，未知字段允许留空。
- [ ] 现有 CSV 导入明确发现末端越界，经确认修订后生成新草稿。
- [ ] Related Tasks 在本阶段显示真实空状态，为后续模块保留路由。

### D. Frames & QC

- [ ] 初始无帧时显示空状态，选择目标时间、帧数和间隔后点 Generate frames 才处理。
- [ ] 按需创建 workspace/frames/<asset_id>/<group_id>/，生成图片与 manifest.json。
- [ ] 目标帧保证进入该组；偶数帧多取较早一侧，起止处剔除越界帧；同一实际帧只保存一次。
- [ ] 展示实际图片、目标标识、请求/实际时间与偏差。重复同配置复用有效缓存，换配置产生新组。
- [ ] 刷新后读取已生成帧组；状态区分生成中、完成、失败、source changed。
- [ ] 在接口中提供帧组列表，供后续 Quick test 单选和 Tests 多选复用。
- [ ] Aria VRS 处理检查 RGB 流并使用 DEVICE_TIME；原始文件不被代理或抽帧覆盖。

### E. 第一阶段交付验收

- [ ] 启动后看见试验 MP4，可连续播放、拖动 seek、切换素材。
- [ ] 修改边界与阶段后 Save，检查磁盘 JSON，再重启页面确认一致。
- [ ] 生成一组真实图片，检查文件、目标帧、manifest 时间戳及缓存复用。
- [ ] 临时媒体样本覆盖重名导入、目录重命名、外部文件变化、删除影响和读取失败。
- [ ] 通过前端类型检查/构建、后端 lint，以及文件操作、标注冲突和时间映射的针对性测试。
- [ ] 浏览器完成“列表 → 视频 → 标注保存 → 手动生成帧 → 刷新恢复”。
- [ ] 交付启动方式、已知限制与 VRS 已验证/未验证项。
